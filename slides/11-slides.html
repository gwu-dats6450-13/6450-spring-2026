Two Key NLP Tasks

Part-of-Speech (POS) Tagging

POS tagging labels each token with its grammatical role in the sentence.

Common Penn Treebank tags

Tag Meaning Example
NN Noun, singular market
NNP Proper noun Tesla
VBZ Verb, 3rd person rises
VBG Verb, gerund buying
JJ Adjective strong
IN Preposition for, at
DT Determiner the, a
CD Cardinal number 1, billion

"Apple is buying U.K. startup for $1 billion"

POS tags are used as features for downstream tasks like NER, parsing, and coreference resolution.

Named Entity Recognition (NER)

NER identifies and classifies named entities — specific real-world objects — in text.

BIO tagging scheme

NER models tag every token using Begin / Inside / Outside labels:

"Apple  is  buying  U.K.  startup"
 B-ORG  O   O       B-LOC  O
  • B-ORG — first token of an organization
  • I-ORG — continuation of an organization
  • B-LOC — first token of a location
  • O — not part of any named entity

A NerConverter merges B-/I- sequences into complete spans: Apple (ORG), U.K. (LOC).

Common entity types

Label Examples
PERSON Elon Musk, Janet Yellen
ORG Tesla, Federal Reserve
LOC / GPE Texas, New York, France
DATE Monday, Q3 2024
MONEY $1 billion, €500M

Use cases

  • Knowledge graph construction
  • Content tagging & search indexing
  • Financial entity tracking in news
  • PII detection for compliance

Pretrained Pipelines

What are Pretrained Pipelines?

A pretrained pipeline is a ready-to-use chain of annotators — trained, serialized, and downloadable in one call.

import sparknlp
from sparknlp.pretrained import PretrainedPipeline

# Download and load a pretrained pipeline by name and language
pipeline = PretrainedPipeline("explain_document_ml", lang="en")

Benefits

  • No training required
  • Versioned, reproducible
  • Cover common NLP tasks out of the box
  • Thousands of models at sparknlp.org/models

What’s inside

Each pipeline is a full annotator chain: DocumentAssembler → SentenceDetector → Tokenizer → [task-specific annotators]

Common Pretrained Pipelines

Pipeline Task
explain_document_ml Tokenize, lemmatize, POS, NER (ML)
explain_document_dl Same with deep-learning models
recognize_entities_dl NER with DL embeddings
analyze_sentiment Sentence-level sentiment
clean_stop Stop-word removal
match_datetime Date/time extraction

ML vs DL tradeoffs

ML pipelines

  • Faster, lighter
  • Good for CPU-only clusters
  • Slightly lower accuracy

DL pipelines

  • Higher accuracy
  • Require more memory
  • Benefit from GPU nodes

Using a Pretrained Pipeline on Raw Text

from sparknlp.pretrained import PretrainedPipeline

pipeline = PretrainedPipeline("explain_document_ml", lang="en")

result = pipeline.annotate("Apple is looking at buying U.K. startup for $1 billion")

# result is a dict of annotation lists
print(result["token"])
# ['Apple', 'is', 'looking', 'at', 'buying', 'U.K.', 'startup', 'for', '$', '1', 'billion']

print(result["lemma"])
# ['Apple', 'be', 'look', 'at', 'buy', 'U.K.', 'startup', 'for', '$', '1', 'billion']

print(result["pos"])
# ['NNP', 'VBZ', 'VBG', 'IN', 'VBG', 'NNP', 'NN', 'IN', '$', 'CD', 'CD']

print(result["ner"])
# ['B-ORG', 'O', 'O', 'O', 'O', 'B-LOC', 'O', 'O', 'O', 'O', 'O']

Pretrained Pipeline on a DataFrame

from pyspark.sql import SparkSession
from sparknlp.pretrained import PretrainedPipeline

pipeline = PretrainedPipeline("explain_document_ml", lang="en")

news_df = spark.createDataFrame([
    (1, "Tesla shares rose after Elon Musk announced new factory in Texas."),
    (2, "Federal Reserve raises interest rates amid inflation concerns."),
    (3, "Amazon acquires Whole Foods in $13.7 billion deal."),
], ["id", "text"])

# .transform() runs as a distributed Spark job — use for large DataFrames
result_df = pipeline.transform(news_df)
result_df.select("id", "token.result", "ner.result").show(truncate=False)

Note

.annotate("text") → runs as a LightPipeline (single string, local) .transform(df) → runs as a full Spark pipeline (distributed, scalable)

NER with a Pretrained Model

from pyspark.ml import Pipeline
from sparknlp.base import DocumentAssembler
from sparknlp.annotator import (
    SentenceDetector, Tokenizer,
    WordEmbeddingsModel,
    NerDLModel, NerConverter
)

doc = DocumentAssembler() \
    .setInputCol("text") \
    .setOutputCol("document")

sent = SentenceDetector() \
    .setInputCols(["document"]) \
    .setOutputCol("sentence")

tok = Tokenizer() \
    .setInputCols(["sentence"]) \
    .setOutputCol("token")

emb = WordEmbeddingsModel.pretrained("glove_100d") \
    .setInputCols(["document", "token"]) \
    .setOutputCol("embeddings")

ner = NerDLModel.pretrained("ner_dl") \
    .setInputCols(["sentence", "token", "embeddings"]) \
    .setOutputCol("ner")

conv = NerConverter() \
    .setInputCols(["document", "token", "ner"]) \
    .setOutputCol("entities")

Pipeline flow

text column
    ↓
DocumentAssembler  →  document
    ↓
SentenceDetector   →  sentence
    ↓
Tokenizer          →  token
    ↓
WordEmbeddingsModel →  embeddings
    ↓
NerDLModel         →  ner  (B-/I- tags)
    ↓
NerConverter       →  entities (grouped)

NerConverter merges B-ORG I-ORG I-ORG sequences into a single entity span.

NER Pipeline Results

nlp_pipeline = Pipeline(stages=[doc, sent, tok, emb, ner, conv])
model = nlp_pipeline.fit(spark.createDataFrame([[""]]).toDF("text"))
result = model.transform(news_df)

result.select("text", "entities.result", "entities.metadata").show(truncate=False)
# +-------------------------------------------------------------------+---------------------------+
# |text                                                               |result                     |
# +-------------------------------------------------------------------+---------------------------+
# |Tesla shares rose after Elon Musk announced new factory in Texas.  |[Tesla, Elon Musk, Texas]  |
# |Federal Reserve raises interest rates amid inflation concerns.     |[Federal Reserve]          |
# |Amazon acquires Whole Foods in $13.7 billion deal.                 |[Amazon, Whole Foods]      |
# +-------------------------------------------------------------------+---------------------------+

NerConverter groups B-/I- BIO tags into complete entity spans with their type label, making downstream aggregation much simpler.

LightPipeline for Fast Inference

LightPipeline Recap and Usage

A LightPipeline wraps a fitted Spark NLP pipeline for fast, local inference — no Spark task overhead.

from sparknlp.base import LightPipeline

# Wrap any fitted pipeline model
light = LightPipeline(fitted_pipeline_model)

# Single string
result = light.annotate("Apple acquired Beats Electronics in 2014.")
print(result["entities"])
# ['Apple', 'Beats Electronics', '2014']

# Batch of strings (still local, no Spark distribution)
texts = [
    "Google opens new office in London.",
    "WHO warns of new health risks in Southeast Asia.",
]
results = light.annotate(texts)
for r in results:
    print(r["entities"])

When to use LightPipeline

  • Interactive exploration / notebooks
  • REST API inference endpoints (< 50K documents)
  • Debugging pipeline outputs on sample rows

LightPipeline vs. Spark Pipeline

LightPipeline Spark Pipeline
Input String or list of strings Spark DataFrame
Distribution Single driver, local Distributed across cluster
Best for < 50K docs, APIs, debugging Large-scale batch processing
Method .annotate() .transform()
Overhead Minimal Spark task scheduling
Output Python dict DataFrame with annotation columns

Tip

Use PretrainedPipeline("name") — it gives you both interfaces automatically: .annotate() → LightPipeline .transform() → full Spark pipeline

Processing News Articles: Full Pipeline

from pyspark.ml import Pipeline
from sparknlp.base import DocumentAssembler
from sparknlp.annotator import (
    SentenceDetector, Tokenizer,
    WordEmbeddingsModel,
    NerDLModel, NerConverter
)

doc = DocumentAssembler() \
    .setInputCol("text") \
    .setOutputCol("document")

sent = SentenceDetector() \
    .setInputCols(["document"]) \
    .setOutputCol("sentence")

tok = Tokenizer() \
    .setInputCols(["sentence"]) \
    .setOutputCol("token")

emb = WordEmbeddingsModel \
    .pretrained("glove_100d") \
    .setInputCols(["document", "token"]) \
    .setOutputCol("embeddings")
ner = NerDLModel.pretrained("ner_dl") \
    .setInputCols(
        ["sentence", "token", "embeddings"]) \
    .setOutputCol("ner")

conv = NerConverter() \
    .setInputCols(
        ["document", "token", "ner"]) \
    .setOutputCol("entities")

pipeline = Pipeline(
    stages=[doc, sent, tok, emb, ner, conv]
)

# Fit on empty DataFrame (pretrained weights only)
empty = spark.createDataFrame(
    [[""]]).toDF("text")
model = pipeline.fit(empty)

# Run on full news corpus
result_df = model.transform(news_df)

Analyzing NER Output

from pyspark.sql import functions as F

# Explode the entities array so each entity is its own row
entities_df = result_df \
    .select(
        "id",
        F.explode("entities").alias("entity")
    ) \
    .select(
        "id",
        F.col("entity.result").alias("entity_text"),
        F.col("entity.metadata.entity").alias("entity_type")
    )

# Most frequently mentioned organizations
entities_df \
    .filter(F.col("entity_type") == "ORG") \
    .groupBy("entity_text") \
    .count() \
    .orderBy("count", ascending=False) \
    .show(10)

# Co-occurrence: which people appear alongside which organizations?
entities_df \
    .filter(F.col("entity_type").isin(["PERSON", "ORG"])) \
    .groupBy("id", "entity_type") \
    .agg(F.collect_list("entity_text").alias("entities")) \
    .show(5, truncate=False)

From Batch to Streaming

Up to now, we’ve worked with batch data

Processing large, already-collected batches of data.

Batch examples

Examples of batch data analysis?

  • Analysis of terabytes of logs collected over a long period of time

  • Analysis of code bases on GitHub or large repositories like Wikipedia

  • Nightly analysis on datasets collected over a 24-hour period

Streaming examples

Examples of streaming data analysis?

  • Credit card fraud detection

  • Sensor data processing

  • Online advertising based on user actions

  • Social media notifications

IDC forecasts that by 2025 IoT devices will generate 79.4 zettabytes of data.

How do we work with streams?

Processing every value from a stream of data — values that are constantly arriving.

DStreams (Legacy)

Spark solved this with DStreams — via microbatching

DStreams are represented as a sequence of RDDs.

A StreamingContext is created from an existing SparkContext:

sc = ...
ssc = StreamingContext(sc, 1)   # batch interval: 1 second

Important constraints of StreamingContext

  1. Once started, no new streaming computations can be set up

  2. Once stopped, it cannot be restarted

  3. Only one StreamingContext can be active per Spark session

  4. stop() on StreamingContext also stops SparkContext

  5. Multiple contexts can be created as long as the previous one is stopped first

DStreams had significant issues

  • No unified API for batch and stream: Developers had to explicitly rewrite code to use different classes when converting batch jobs to streaming jobs.

  • No separation between logical and physical plans: Spark Streaming executes DStream operations in exactly the sequence specified — no scope for automatic optimization.

  • No native event-time window support: DStreams only support windows based on processing time (when Spark received the record), not event time (when the record was actually generated). This made building accurate pipelines difficult.

Structured Streaming

What is Structured Streaming?

A single, unified programming model for batch and stream processing

Familiar SQL or batch-like DataFrame queries work on your stream exactly as they would on a batch — fault tolerance, optimization, and late data are handled by the engine.

A broader definition of stream processing

The line between real-time and batch processing has blurred significantly. Structured Streaming supports anything from continuous streaming to periodic micro-batch (e.g., every few hours) with the same code.

The Programming Model

The Programming Model

  • Every new record in the data stream is a new row appended to an unbounded input table
  • Spark automatically converts the batch-like query to a streaming execution plan (incrementalization)
  • Spark figures out what state to maintain to update results as records arrive
  • Triggering policies control when results are updated

Specifying output mode

Append mode

Only new rows added to the result table since the last trigger are written to output. Applicable only when existing rows cannot change (e.g., map operations on input streams).

Update mode

Only rows that were updated since the last trigger are written. Requires a sink that supports in-place updates (e.g., a database table).

Complete mode

The entire updated result table is written to output after every trigger. Typically used with aggregations.

The 5 Fundamental Steps

Overview

  1. Define input sources

  2. Transform data

  3. Define output sink and output mode

  4. Specify processing details

  5. Start the query

1. Define input sources

spark = SparkSession...

lines = (spark
    .readStream.format("socket")
    .option("host", "localhost")
    .option("port", 9999)
    .load())
  • readStream (not read) signals a streaming source
  • This sets up configuration only — data reading begins when the query starts
  • Besides sockets, Spark natively supports Apache Kafka and file-based formats (Parquet, ORC, JSON)
  • A query can define multiple input sources, combined with unions or joins

2. Transform data

from pyspark.sql.functions import *

words = lines.select(split(col("value"), "\\s").alias("word"))
counts = words.groupBy("word").count()
  • Use the usual DataFrame operations — they work identically on streaming DataFrames
  • The same code runs as both a batch query and a streaming query

3. Define output sink and output mode

writer = counts.writeStream \
    .format("console") \
    .outputMode("complete")
  • format: "console", "parquet", "kafka", "memory", etc.
  • outputMode: "append", "update", or "complete"

4. Specify processing details

checkpointDir = "..."

writer2 = (writer
    .trigger(processingTime="1 second")
    .option("checkpointLocation", checkpointDir))

Triggering options:

  • Default: Next micro-batch triggers as soon as the previous one completes
  • Processing time interval: Fixed interval (e.g., "1 second", "5 minutes")
  • Once: Exactly one micro-batch — useful for scheduled runs to control cost
  • Continuous: Experimental as of Spark 3.0 — low-latency, millisecond processing

5. Start the query

streamingQuery = writer2.start()

# Block until query terminates (or use await in notebooks)
streamingQuery.awaitTermination()

Spark Streaming Under the Hood

Spark Streaming under the hood

  1. Spark SQL analyzes and optimizes the logical plan to ensure incremental, efficient execution on streaming data.

  2. Spark SQL starts a background thread that continuously executes a loop.

  3. The loop continues until the query is terminated.

The execution loop

Each iteration:

  1. Based on the configured trigger, the thread checks streaming sources for new data.

  2. New data is executed as a micro-batch — an optimized execution plan reads the data, computes the incremental result, and writes output to the sink.

  3. The exact range of data processed and any associated state are checkpointed to allow deterministic reprocessing on failure.

The loop terminates when…

  1. A failure occurs (processing error or cluster failure) → restart from last checkpoint

  2. The query is explicitly stopped via streamingQuery.stop()

  3. The trigger is set to Once → stops after processing all available data

Data Transformations

Stateless vs. Stateful transformations

Each execution is a micro-batch. Operations fall into two categories:

Stateless transformations

select(), explode(), map(), flatMap(), filter(), where() — each input record is processed independently, with no memory of previous rows.

  • Supports append and update output modes (not complete)
  • Safe to use with append-only sinks like files

Stateful transformations

groupBy().count() and other aggregations require maintaining state — a running tally across micro-batches.

  • State is held in executor memory and checkpointed to disk for fault tolerance
  • Supports all three output modes
  • The engine automatically manages state lifecycle for correctness

Stateful Streaming Aggregations

Types of stateful aggregations

Structured Streaming supports two classes:

  • Aggregations by key — e.g., streaming word count grouped by word

  • Aggregations by event-time window — e.g., count records received per 5-minute window

Event-time windows — tumbling

Non-overlapping, fixed-size windows. Each event falls in exactly one window.

Event-time windows — sliding

Overlapping windows of fixed size and stride. An event can fall in multiple windows.

Updated counts after each trigger

Handling late data — watermarks

Late-arriving data is common in distributed systems (network delays, out-of-order records). A watermark tells Spark how late data can be while still being included.

A watermark is a moving threshold in event time that trails behind the maximum event time seen by the query. The trailing gap — the watermark delay — defines how long the engine waits for late data.

Defining a watermark in code

from pyspark.sql.functions import window

windowedCounts = (words
    .withWatermark("timestamp", "10 minutes")   # tolerate 10 min of lateness
    .groupBy(
        window(col("timestamp"), "5 minutes", "1 minute"),  # 5-min sliding windows
        col("word")
    )
    .count()
)
  • Records older than (max observed event time − watermark delay) are dropped
  • Enables memory-bounded state management for long-running streams
